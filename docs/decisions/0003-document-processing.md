# ADR 0003 — Document processing and PDF output

- **Status:** Accepted
- **Date:** 2026-10-05

## Context

Phase 3 needs robust EPUB parsing/export, PDF text extraction, structure-aware
segmentation, and reflowed PDF output that supports Unicode and RTL. The build
environment has no system libraries (pango/cairo/gdk-pixbuf) and no installed
fonts, and packages cannot be installed system-wide. The package policy requires
stable, Python-3.14-compatible releases and forbids shipping code that cannot be
verified.

## Decision

- **EPUB:** standard-library `zipfile` + `lxml`. Inspect required (`EbookLib`
  rejected — less control over safety and raw structure).
- **PDF input:** `PyMuPDF` (fast, mature, pure wheel with Unicode text and image
  extraction).
- **Sentence segmentation:** `pysbd` (offline, multilingual) with graceful
  paragraph fallback.
- **PDF/HTML output:** a configuration-driven `render_backend`:
  - `pymupdf` **(default)** — a print-ready book PDF (cover, contents with page
    numbers, running heads, page numbers, outline) via PyMuPDF's Story engine;
    pure Python, no system libraries, RTL-aware.
  - `html` — reflowed HTML generated by our own renderer; always available,
    fully testable.
  - `weasyprint` — optional `pdf` extra for an alternative PDF backend; requires
    pango/cairo/gdk-pixbuf. A clear `ConfigurationError` is raised when it (or a
    configured backend) is unavailable.
- **EPUB** — rebuilt with cover, book CSS, embedded fonts, EPUB 3 `nav` and
  legacy `toc.ncx`.

## Rationale

- Building the canonical model on `zipfile`+`lxml` keeps archive safety and
  structure preservation under our control rather than a library's.
- `PyMuPDF` is the strongest maintained extractor and ships self-contained
  wheels.
- Making rendering a pluggable, configured backend means the pipeline works
  everywhere (pure-Python `pymupdf` book PDF) and can upgrade to `weasyprint`
  where the native stack and the `pdf` extra are present, instead of failing
  obscurely or shipping unverifiable code.
- The reflowed document (not the HTML/PDF bytes) is the tested artifact of the
  output adapter; presentation is delegated to the backend.

## Consequences

- In constrained environments the default output is a self-contained PyMuPDF
  book PDF plus an EPUB; enable `weasyprint` where the native libraries and the
  `pdf` extra are present.
- OCR remains an interface (`OcrProvider`) with a null default; no OCR provider
  is mandatory.
